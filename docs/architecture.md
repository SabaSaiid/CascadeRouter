# Current local architecture

The current Pydantic models and generated OpenAPI are authoritative. The earlier
hosted-provider/sandbox blueprint is retained in Git history, not implemented by
this branch. See [SECURITY.md](../SECURITY.md) for tested controls and trust limits,
and [release gates](release-gates.json) for verification status.

## Analysis and durable identities

`backend.main.create_app` wires validated `BackendConfig`, API middleware and local
services. The supported CLI is `python -B -m backend.main --config ABSOLUTE_JSON`.
Repository access is denied without explicit policy/storage. The compiler adapter
uses `ast_scanner.py` and `dag_builder.py` without importing target modules; source
capture retains private version identities. `ScanService` bounds asynchronous
admission and retains immutable analysis snapshots in `AnalysisStorage`.

`backend/schemas.py` defines strict shared contracts. The frontend's
`services/contracts.ts` is generated by `frontend/scripts/sync_contracts.py`;
`tests/unit/test_frontend_contract.py` prevents OpenAPI drift. Compiler dataclasses
remain internal; no second public DTO or inferred dependency model replaces them.

## Local benchmark and decision path

`JobService` uses finite local workers, persistent immutable plans and transactional
progress. It supports explicit deterministic test executors and the approved offline
recorded-data engine. `benchmark_cases.py`, `benchmark_assets.py` and
`offline_benchmark.py` bind registry/case/profile/capture identities, local approval
and provenance. The evaluator checks available captured/local cases; the metrics
aggregator preserves availability and sample populations. No provider is invoked.

`OptimizationService` authenticates retained evidence before the compiler optimizer
considers eligibility and verified cost. Policy generation serializes its decisions;
it neither activates runtime dispatch nor edits source. Test evidence and missing
approval remain unavailable. See [offline benchmarks](offline-benchmark.md),
[jobs](benchmark-jobs.md), and [optimization](optimization.md).

## Proposal and static validation path

`PatchService` combines retained optimization, analysis and private source manifests.
`source_manifests.py` reuses guarded source reads; `patch_generator.py` verifies
literal ranges and constructs candidates in memory. `patch_validator.py` shares
bounded candidate syntax and AST checks. `literal-spans.v1` review artifacts and
validation reports are integrity-bound immutable records in SQLite schema 5.
Source is never applied or application-tested. Report retrieval is historical;
request a new observation to check source freshness again.
See [proposals](patches.md) and [static validation](patch-validation.md).

## Frontend and runtime boundaries

`frontend/src/App.tsx` coordinates the existing workbench. The single domain client
uses `LocalTransport` for explicit loopback HTTP, bounded JSON, cancellation,
controlled failures and response checks. Operation generations prevent stale results
from overwriting newer state. Views display actual backend evidence, partial/empty
states and test/recorded restrictions. Demo scans are explicit and disable backend
operations. There is no silent fixture fallback or mount-triggered submission.

The separately consumed `CascadeRouter` Python runtime accepts explicitly registered
local executors and authorized fallback. The UI provides policy review only. No
provider SDK, cloud queue, hosted runtime, credential loader, application sandbox,
source-application step or automatic regression execution is part of this design.

## Validation and release preparation

Trusted tests live under `tests/`, with `tests/fixtures/` excluded from collection.
Frontend tests use Node's runner, generated contracts, deterministic fixtures and
React server rendering. Real loopback acceptance crosses the actual TypeScript
client, API and durable storage. This is not a browser test or proof of a genuine
approved production benchmark-to-patch journey.

Release helpers under `scripts/` and `frontend/scripts/` inspect metadata and local
artifacts; they do not execute targets or replace actual build/test gates. The
[authoritative gate register](release-gates.json) links retained and current evidence.
No version, release tag, package publication or production-readiness claim is implied.
